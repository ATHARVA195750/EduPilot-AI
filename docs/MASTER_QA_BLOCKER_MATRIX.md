## Root Infrastructure Findings

- The `.env` project URL and `supabase/.temp/linked-project.json` both match the project ref documented as the real institute in `supabase/config.toml`. The current environment is therefore unsafe for test writes.
- `.env` contains the application URL and anon key; it is ignored by git. No `.env.qa` or `.env.test` exists. Variable names only were inspected; values are not reproduced here.
- No `@playwright/test`, Playwright config, or Playwright browser existed at campaign start. The package has now been added and Chromium installation attempted.
- `supabase` CLI and Docker are unavailable, so this machine cannot start a local Supabase stack or safely provision/link a new project through the CLI.
- `supabase/schema.sql` is an older baseline and does not represent the full live database. Repository migrations include proposed authorization migrations. Do not apply these to production or assume `supabase db push` is a safe QA bootstrap.
- Supabase JS is installed and can be used by a Node-only setup helper with the QA service key. That key must never be passed into Vite/browser code.
- Current shared browser has the login page; earlier network events include an aborted logout request. Recent snapshot showed no active network error, but it does not prove backend reachability.
